# Application workbench design

The browser display makes application material readable inside a shared inspection shell.
Applications choose content and priorities. Jig owns layout, navigation and evidence access.

## Principles

1. Let purpose determine presentation. Reading, observing, comparing and investigating are complete uses.
2. Identify each scope without unnecessary repetition. The shared header identifies the selected application view.
3. Give each region an obvious owner. A selected record owns its inspector, while About this view describes the publisher.
4. Give prominence according to relevance. Show the useful material first and retain important caveats visibly.
5. Choose density appropriate to the material. Align comparison rows and give documents and photographs reading room.
6. Make interactions clear when present. Display-only content needs no invented commands or compulsory inspector.
7. Preserve orientation through change. Keep selection, execution, application outcome, evidence availability and observation freshness distinct.

## Rendering commitments

- Keep the application summary visible. Authors can use it to describe uncertainty or partial results.
- Use one page identity in the shared header. Avoid repeated headings when a section contains one identically named collection.
- Put search and sorting beside their collection. Counts describe retained records and disclose reported totals.
- Gallery images and captions lead. Preserve every supplied column in a metadata disclosure.
- Choose layouts from supplied block types and explicit presentation roles, independently of application names or example fields.
- Keep material rendering consistent for root and attributed child publishers.
- Disclose collection tools when they would dominate small datasets. Keep active filters discoverable.
- Pair supplied comparison material with its validation context without application-specific field inference.
- Preserve document images' proportions and full content, including charts and screenshots. Keep captured-source disclosures accessible for content and covers.
- Use readable prose surfaces for correspondence. Preserve whitespace, code and literal diff formatting.
- Place adjacent reading sections beside each other when space permits. Keep authored order when they stack.
  Unpaired reading sections use the full bounded reading width.
- Render captured text and patches inline. Complete rectangular CSV excerpts can use a table with raw text available.
- Preserve authentication, exact capture identity, preview bounds and cleanup. No authored URL or path grants file access.
- Keep the selected record when filters hide it. Explain that scope and provide Clear filters without changing selection.
- Preserve collection-search focus and caret when updates move a collection into a comparison layout.
- Open an inspector only when requested. Highlight its owning record and preserve the return path.
  Keep long desktop inspectors scrollable within the available workspace.
- Return from captured evidence to its exact reference after a publisher update replaces a section. Never focus a different reference merely because its button occupies the old position.
- If the selected delivered file disappears, show the remaining inventory and explain the lost selection without opening another file.
- Keep incomplete results, stopped publishers, clipped content and stale observations explicit.

## Application map

An optional live Run map follows authored application pages in navigation.
It shows the admitted components and slots available to call, separately from the observed-call tree.
Connections do not establish order, internal conditions or data transformations.

The map leads immediately below a compact toolbar, without repeating its page title.
Callers sit left of their configured targets, with complete slot labels and request counts beside each connection.
Cards and connections share one coordinate space, including during zoom.
Fit shows the whole map, while 100% restores natural text size.
Automatic fitting never reduces text below 75%.

The chooser includes incoming caller and slot context when labels repeat.
Selecting a component reveals its requests, incoming callers and configured child calls.
Each available slot has its own retained request count, even when slots share one target.
The Run root shows workspace facts without inventing a child request.
Native resource kinds have human names, and checkpoints stay reachable with quieter styling.

Observed connections have distinct emphasis, with literal request states beside each component and slot.
Repeated invocations retain mixed summaries, such as “2 returned · 1 failed”.
One slot's observations never describe every slot sharing its target.
Returned requests do not establish application success.

All requests, Active and Needs attention change emphasis without hiding the configured map.
Active follows active requests. Needs attention follows failed or uncertain requests.
When Needs attention is selected, show a compact index of exact failed and uncertain requests, including those not placed on the map. It is retained evidence, not complete execution history, and links are unavailable while stale.
Requested cancellation retains its own wording without becoming an inferred failure.
Summary space stays stable as observations change, preserving route geometry and the viewer's position.

Preserve selection, zoom and canvas position across refresh and inspection return by exact Run and component identities.
Opening a particular invocation reveals its ancestry without an unrelated filter hiding it.
Unavailable composition, omitted observations and unplaced requests remain explicit.
Absence of a retained request does not establish a skipped call.

An invocation can open views published by its exact accepted child source.
Show the complete authored material and retain a return to the invocation and its selected component.
Missing or ambiguous child identity has an explicit unavailable state.
Stale observations disable navigation without hiding the retained material.

## Project exploration

`jig explore` opens approved application structure before execution.
A persistent workflow list chooses an exact Flow or Binding. The selected map occupies the main workspace.
The approved entrypoint selects the initial root, without inventing a Run or applying hidden input defaults.

Configuration maps use a Selected root badge and configured-call counts.
They show no request totals, execution state or elapsed time.
Approval describes retained meaning, not fresh environment verification.
Refresh rereads approved configuration. A stale response keeps its readable map while disabling launch.

Run with input opens a focused panel beside the map.
Component details and Run input take turns using the available inspection space.
Narrow layouts give the requested panel the full workspace and preserve a clear return.
The input begins blank. Show the declared schema and file or channel requirements without inventing example data.

Explicit Run submits the exact input and selected approval once.
Lost acknowledgment triggers status reads, never resubmission.
Read the active Run before looking up the unresolved request.
A retained refusal resolves that request without replacing another active Run.
A missing request record remains unknown and cannot enable launch.

The explorer shows preparation, active, settled, refused and uncertain states separately.
An Open run link opens the ordinary read-only observer in another tab.
The explorer retains input and map context for the next run.

Only one Run can be active in this exploration session.
Closing the explorer stops owned active work through ordinary cleanup.
This consequence stays visible beside the Close action and in the footer.
Closing a separate inspection remains presentation-only.
An unconfirmed Close keeps new Runs disabled, even when later status reads report idle.

## Acceptance checks

Review the same material in light, dark and monochrome themes at desktop and narrow widths.
Check keyboard focus, coarse-pointer targets, text contrast and responsive detail navigation.

- Photos and Organise show photographs directly, with readable captions and quiet technical metadata.
- Support shows the customer request and draft reply before process details.
- Kitchen compares all shifts in one timetable, with checked and pending assignments distinguished.
- Contacts leads with completed records, retaining mapping and correction reasons.
- Patch review displays captured patches alongside their independently validated checks.
- Plain reports remain useful without selection, search or commands.
- Filtering never silently changes the inspected record. Clearing filters returns focus to its visible control, or the detail Back button on narrow layouts. Typing in search retains focus.
- Unavailable evidence remains a readable state, without a broken image or fabricated successful result.
- Application maps preserve every supplied component and slot, including long labels and shared targets.
  Cards occupy distinct positions, connections meet their boundaries, and small compositions avoid oversized empty canvases.
  Zoom preserves a shared coordinate space and keeps the selected component reachable.
  Duplicate labels stay distinct, repeated requests stay separate, and stale invocation links remain disabled.
  Keyboard selection, narrow-layout Back and return from invocation details preserve orientation.
- Mixed request states remain readable on components and individual slots, including in monochrome.
  Focus changes preserve geometry and keyboard reachability. Observed updates never move components or connections.
  Exact child-view navigation preserves the invocation context, including when view names or subjects match other publishers.
- Project exploration starts without execution and preserves exact workflow identity through selection and refresh.
  Invalid input, missing prerequisites, stale configuration and unconfirmed submissions cannot silently launch another Run.
  Configuration-only maps show no invented observations. Run handoff preserves the explorer's draft and context.
- Execution starts with readable call identities and observed states. Inspection opens only after selection.
- Delivered files show their verified inventory without an empty compulsory detail pane.
- Activity prioritizes retained report text while keeping severity, source and history discoverable.
- Diagnostics preserve complete retained causes, attribution, clipping and operation paths.
- Every host detail pane closes with Escape and preserves a visible return path at narrow widths.
- Narrow screens expose every destination through a labeled native view chooser. Desktop navigation retains vertical tabs.
- Tables size short columns compactly and preserve readable identifiers. Overflow controls reveal the remaining columns.
- Appearance remains reachable on narrow screens.
