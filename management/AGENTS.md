# Deferred product work

## Purpose

Preserve actionable follow-up work that improves capability compounding or
power under control without turning every improvement into a release gate.

## Ownership

- `inbox/*.md` records postponed tasks, their scope and completion criteria.
- The roadmap owns outcome order; specifications own current behavior.
- Temporary execution plans, diagnostics and evidence remain in `.tmp/`.

## Local Contracts

- Write each task as a standalone entrypoint with the problem, proposed scope,
  exclusions and an observable completion condition.
- Record whether work is deferred until after the first public launch.
- An inbox item preserves work; it does not authorize implementation or spending.

## Work Guidance

- Update an existing task rather than creating competing descriptions.
- Keep investigation history and private operational details out of task files.
