# Project Authoring Probe/1 disposition

**Status:** passed on 2026-08-29 for the bounded public authoring campaign.
This closes the authoring gate; it does not claim an operational Jig host,
native dependency preparation, or Starter quality.

## 1. Campaign boundary

One clean-room author received only a sealed packet containing the relevant
portable specifications, public machine schemas, packed candidate packages,
fixed fixtures, and finite setup/check instructions. The author could not read
the Jig repository, private implementation, roadmap, or evaluator material.
The platform was frozen while the author consumed it.

The requested project contained:

```text
one zero-configuration Python Run Flow
    -> directly eligible

one configured Bun Run Flow
    -> one Binding with exact settings
    -> one exact child-Flow slot to the Python Flow
```

It deliberately excluded Agents, Semantic Choice, Hooks, Services, Journal,
changing target sets, and administration. This made the direct-target versus
Binding boundary independently observable.

## 2. Independent result

The final evaluator record passed every one of its 15 bounded gates:

- packet and submission integrity;
- exact source tree and import allowlist;
- TypeScript checking and Python compile/import;
- both inert FLOW package checks;
- all 22 valid/invalid Schema/1 fixture cases;
- bounded default-deny project evaluation;
- deterministic project linking;
- direct Python Run/1 execution;
- Bun parent execution with exactly one child call;
- complete child-result preservation;
- operational child-failure propagation;
- evaluator-host deadline/no-redispatch behavior; and
- bounded clean process shutdown.

The independent structural result and the release-owner private evaluator and
linker result agreed exactly on two packages, Binding `reviewer`, direct target
`flow:flows/normalizer`, configured target `binding:reviewer`, and the sole
slot edge from `reviewer.normalizer` to the direct Flow. No capability,
attachment, Hook, Service, Agent, or other authority appeared.

The private finite Project Session also produced an applicable admission Plan
for an isolated copy, proving that the frozen public declarations pass the
actual bounded evaluator, linker, runtime planning, and review path. That was
inert planning evidence only; the campaign did not apply or launch through an
operational Jig host.

## 3. What the campaign changed

The author discovered one real TypeScript SDK defect: an interface-shaped
`RunResult` could not be retained directly inside `JsonValue` without
rebuilding or casting it. The equivalent readonly type alias now has the exact
structural JSON meaning, obsolete internal casts are removed, and packed type
coverage proves direct and nested assignment. Wire behavior is unchanged.

No new Project Authoring helper, discovery form, Binding field, runtime
profile, command template, or administration operation was invented to make
the campaign pass. The public declaration interface was sufficient.

Setup exposed two campaign-harness frictions—offline archive extraction and
the TypeScript platform compiler artifact. They were corrected in the sealed
packet rather than promoted into Jig semantics.

## 4. Product consequences

The campaign fixes the minimal authoring conventions needed by a later
`jig init --bare`:

- one ordinary `jig.ts` using explicit shallow `discover("./flows")` and
  `discover("./bindings")` defaults;
- ordinary editable `flows/` and `bindings/` roots;
- native manifests beside code-backed Flows; and
- no default Hook, Agent, Service, Semantic Choice, or application ontology.

The campaign does not justify copying its two example Flows into a bare
project. Bare initialization should create the proven project envelope, not a
sample application or a composable Starter algebra.

The next operational gate remains exact native dependency preparation. The
campaign could execute components only because its sealed external setup had
already installed `@flowmd/sdk` and `flowmd_sdk`. The private Jig planner
correctly linked both packages and observed exact host recipes, but no Jig
preparation owner installed or sealed those declared dependencies. Direct
component evidence must not be relabelled as Runtime Adapter readiness.

## 5. Exact nonclaims

This checkpoint does not establish:

- a public project opener or operational CLI;
- a production administrator-owned trust root;
- native dependency preparation or lock reproducibility;
- an operational Jig-host Run;
- a public Runtime Adapter or Sandbox Backend interface;
- Agent, Semantic Choice, Hook, Service, or general orchestration conformance;
- Starter quality; or
- publication readiness of either package.

Project Authoring Probe/1 should be rerun unchanged after the finite public
CLI, dependency-preparation, and installation boundaries land. Later probes
receive only their relevant frozen public surface and may not mutate the
platform while consuming it.
