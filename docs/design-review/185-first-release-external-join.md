# First-release external-join disposition

**Status:** accepted on 2026-08-29 after the public changing-source campaign
and cancellation checkpoint. The next executable critical-path proof requires
protected external substrates. Remaining local release/schema work must close
with that independent consumer rather than substitute for it; this is not
permission to pull later features forward.

## 1. Completed local chain

The following path now has retained implementation evidence:

```text
finite trusted Project Session
    -> public inert projectRunTargets() authoring
    -> complete generation-pinned expansion and review delta
    -> deterministic invocation-local filtering
    -> cancellation-aware complete scan
    -> deterministic zero/many no-allocation closure
    -> durable one-survivor allocation and dispatch
    -> one direct leaf Flow or settings-only Bun Binding child
```

The authoring value passed two independent clean-room consumers and the real
retained evaluator. The Resolver consumes every pinned candidate without
sampling or truncation, closes cancellation before allocation, and reuses the
existing child lifecycle for one supported survivor.

This is enough deterministic machinery for a later routing campaign. It is
not the campaign itself.

## 2. Direct leaves are not Agent workers

The currently executable child profiles deliberately have no capability uses,
attachments, or child-owned operation dispatcher. A selected direct Flow can
perform an exact self-contained leaf job. A settings-only Bun Binding can add
immutable configuration. Neither can invoke Agent Run.

The Agentic Routing mechanism may initially prove that one Agent-backed
chooser selects a direct exact-code leaf from the complete eligible set. The
useful Gauntlet/Majority-style worker campaign requires more:

```text
operator-owned Agent-provider registration
    -> admitted provider generation and lease
    -> configured child Run Binding with exact Agent Run slot
    -> child-owned durable Agent-effect allocation
    -> per-operation skill, attachment and tool attenuation
    -> possible-dispatch/no-redispatch ownership
    -> provider and child fencing before child terminal
```

Root-owned effect rows cannot be reused for a child. Immediate-parent
exclusion remains sufficient for the supported non-recursive leaf profile; a
generic ancestor chain or wait graph is not earned until nested composition or
shared blocking resources exist.

## 3. The three external prerequisites

### 3.1 Retained native SDK artifact

The selected native-preparation proof requires an administrator-owned,
authenticated, retained, restart-reacquirable record for the exact
`@flowmd/sdk@0.0.0` archive. Absence or drift must become exact
`UNAVAILABLE`. Jig must not replace that missing fact with a caller path,
ambient package cache, package-manager lifecycle, Nix integration, generic
artifact registry, or new blob-store SPI.

This blocks real SDK-dependent packages in Operational Baseline/1.

### 3.2 Production host trust root

A fresh supported Linux host must install administrator-owned protected
launcher/helper/subreaper machinery, retain exact Bun and Python support,
publish bounded authenticated read-only receipts, and prove restart
reacquisition plus drift refusal. The current proof-host lease remains valid
evidence but is not an installation contract or distributable Jig feature.

This blocks the external deterministic alpha and an operational public
project opener/CLI.

### 3.3 Operator-owned Agent provider

The host must register one exact retained provider artifact together with the
Agent Run contract/export, authority ceiling, runtime and containment plan,
and restart-reacquirable lifetime. The proof must include durable possible
dispatch, no redispatch after uncertainty, exact skill/tool/attachment
projection, cancellation, deadline, complete fencing, and zero residue.

An ambient coding-agent command, mutable checkout, project package, or
injected callback remains invalid evidence. One real integration does not earn
a public provider SPI.

## 4. Dependent sequence after the join

Once the prerequisites exist, the order remains:

```text
retained SDK artifact + production trust root
    + authenticated acquisition/finite CLI
    + public lock schema and exact installed-consumer gates
    + selected release/package metadata
    -> Operational Baseline/1 on a fresh host

operator Agent provider
    -> private Agent Run to Semantic Choice composition

baseline + composition + changing universe
    -> durable no-rerank Semantic Choice
    -> private direct-leaf routing-mechanism checkpoint
    -> capability-bearing child Agent-worker checkpoint
    -> independent Agentic Routing/1 campaign
    -> first promotional preview milestone

Agentic Routing/1
    -> independent Event Source + minimal Hook campaign
    -> independent software-factory campaign consuming that result
    -> first showcase milestone
```

Semantic Choice authoring, provider Binding, and durable decision ownership
must follow the real composition evidence. Possibly dispatched choice is
`UNCERTAIN` and is never reranked. The direct-leaf checkpoint proves the
selection mechanism without weakening review 168's milestone; the promotional
campaign still requires real Gauntlet/Majority-style workers using child-owned
Agent effects.

## 5. Event Source remains deliberately deferred

The existing Journal/Hook path already proves atomic Event commit, admitted
Hook selection, exact derived-root allocation, lost-wake recovery, and
fencing. It does not justify a second host-origin Journal owner today.

Two tempting early constructions are rejected:

- A direct host-origin append would change Event origin, strict Journal
  reconstruction, durable append ownership, publisher issuance, and
  Project-Session revocation without an independent consumer.
- A private inbox fixture launching a publisher Run would merely retest the
  existing kernel while the operational package/preparation surface is still
  unavailable.

The later independent Event Source/Hook campaign should first attempt the
least-invasive application composition:

```text
foreground host application watcher
    -> RootAdministration.startRun(exact producer Run Binding,
                                   stable observation submission ID)
    -> admitted producer Flow
    -> producer's Journal slot maps to an exact Journal-publisher Binding
    -> canonical Journal Event with source binding:<journal-publisher-id>
    -> admitted Hook
```

If independent builders demonstrate that publisher-Run loss makes Event
identity or no-redispatch semantics impossible, that concrete failure may earn
a private host-origin append owner. A second genuinely different source is
required before any generic Event Source or publisher SPI is considered.

## 6. Release and deferral boundary

License, version, repository metadata, and publication are product/legal
choices. Package hygiene evidence and a proof-host run do not authorize an
alpha label before the fresh-host operational campaign.

The following remain demand-gated rather than substitutes for blocked
first-release work:

- Service conformance debt;
- updates and three-way reconciliation;
- GUI and Cordis-component campaigns;
- Jig Graph or a Sley compiler;
- generic Runtime Adapter, Sandbox Backend, Agent-provider, or Event Source
  SPIs; and
- maximum-size Plan fault-injection coverage.

The correct continuation at this boundary is external substrate coordination
plus the bounded local release/schema work exercised with its consumer, not
additional unrelated platform surface.
