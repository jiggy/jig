# Post-rootless product roadmap

**Status:** selected on 2026-08-31. This is the current product ordering. It
supersedes the release ordering in reviews 165, 168, and 185 without changing
their completed evidence.

## Current boundary

Review 197 proves one private rootless Linux Run mechanism. The proof has the
security properties needed for the first product path, but it is not yet the
mechanism used by an installed Project Session. The repository therefore has
strong private execution evidence and still has no operable Jig alpha.

The immediate job is not to add another subsystem. It is to turn the one
proved mechanism into the smallest complete product path:

```text
installed Jig
    -> acquire one local project
    -> check and review its exact proposal
    -> admit it through one ordinary lock
    -> run one exact target in the rootless envelope
    -> report a finite terminal
    -> close and leave no process or cgroup residue
```

## Ordered product path

Work proceeds in this order:

```text
1. join the rootless mechanism to admitted Project Session/root ownership
2. run author evaluation and necessary native preparation in that mechanism
3. delete the superseded privileged execution path
4. expose one finite installed CLI
       jig init --bare
       jig check
       jig run
5. give only that surface to an independent Operational Baseline/1 consumer
6. publish the deterministic alpha after the baseline passes
7. prove one real contained Agent Run provider
8. add durable Semantic Choice over an exact admitted survivor set
9. run the independent Agentic Routing/1 campaign
10. add one host-owned Event Source and the minimum admitted Hook path
11. rebuild the software-factory campaign from the published surface
```

The CLI is intentionally smaller than the internal state machines. A normal
user does not choose a lock mode, manipulate admission, copy a Plan digest,
select a Backend, or manage a runtime registration. `jig run` may internally
plan, show a review, obtain confirmation when authority changes, apply, run,
and close. Those internal stages remain exact because they protect safety and
recovery; they do not become user workflow.

## Installation and runtime rule

There is no `jig setup`.

Jig may use ordinary prerequisites already supplied by a supported operating
system, and its release may carry finite immutable support bytes needed by its
own implementation. Every package activation must still prove the complete
rootless envelope before package bytes execute. Missing or changed support is
`SANDBOX_UNAVAILABLE`; it never selects a privileged or unsafe fallback.

The next runtime-acquisition proof must choose the smallest solution which can
be installed and revalidated without operator registration. It may not turn
Jig into a package manager, runtime store, daemon, host service, or lifecycle
manager. Native package preparation remains frozen at its one proved
networkless and script-disabled shape until the same rootless mechanism can
execute it end to end.

## First-release exclusions

The following are not on the deterministic-alpha critical path:

- public Runtime Adapter or Sandbox Backend registries;
- Services and complete Service/1 conformance;
- generic provider or effect registries;
- updates and three-way reconciliation;
- GUI and Cordis campaigns;
- Jig Graph or a Sley compiler;
- remote administration, daemon operation, distributed execution, or
  arbitrary list/watch/cancel surfaces; and
- macOS, Windows, Node-host, Deno-host, or Python-control-plane support.

Existing mature private evidence for deferred subsystems need not be deleted
merely because it arrived early. It also must not slow or enlarge the first
product path. If an early subsystem forces new alpha-facing concepts or makes
the rootless join materially harder, remove it from the active product path.

## Release gates

The deterministic alpha is earned only when all of these pass together on a
fresh supported host:

1. installed acquisition requires no Jig-specific setup;
2. the finite CLI exposes no private paths, recipes, cgroups, coordinator
   epochs, admission terms, or Plan digests;
3. one canonical `jig.lock` format has no prerelease migrations;
4. every execution path uses the proved rootless ownership and cleanup
   contract;
5. the independent Operational Baseline/1 consumer succeeds using only the
   shipped CLI and its short public documentation; and
6. the release artifact has a finite supported Bun/Linux range and the
   selected licence, repository, and version metadata.

Agentic Routing and the software-factory showcase remain the next public
milestones, but neither may substitute for the deterministic baseline.

## Governing rule

> Join and simplify what is proved before adding what is merely designed.
