# Stable decision index

This is a traceability aid, not another specification. It lists the durable
architecture decisions and points to their current normative home. Historical
review files remain useful evidence but may contain superseded proposals.

| Area | Stable decision | Normative home |
|---|---|---|
| Layer boundary | FLOW owns the portable boundary; Jig owns admission, resolution, authority, lifecycle, and history; runners retain internal control. | [Reviewed architecture §1](design-review/60-reviewed-architecture.md#1-the-architecture-in-one-view) |
| Package | `FLOW.md` is required; its exact-case filename identifies bounded Metadata/1, whose only required fields are `name` and `description`. Ordinary resources and zero or one obvious `flow.<suffix>` implementation need no manifest DSL or mandatory contract. Any future core vocabulary or semantics requires a discriminator which v1 rejects. | [Reviewed architecture §3](design-review/60-reviewed-architecture.md#3-flow-package1), [Package/1 §2](spec/package-format.md#2-flowmd-metadata1) |
| Instruction mode | A Markdown-only package requires an Agent; exact code wins by default; instruction fallback is explicit in both package and Binding and is selected only before launch. A projection-capable host Agent Binding receives bounded logical resources and returns one complete structured result through Agent Run without another protocol. | [Reviewed architecture §3.3](design-review/60-reviewed-architecture.md#33-instruction-and-exact-implementations), [Agent contracts §3.2](spec/agents-and-semantic-choice.md#32-instruction-conductor-mapping) |
| Runtime selection | FLOW owns no runtime profiles, commands, toolchain versions, or digests. One optional strict selector token narrows trusted host Runtime Adapters; native metadata owns native constraints. Planning pins one implementation recipe or exact unavailability per admission generation; Run/Mount owners derive exact launch after Backend-supervised pinned preparation and never reselect machinery or fallback branches. Ambiguity fails rather than invoking instruction fallback. | [Runtime Adapters/1](spec/runtime-adapters.md), [Project policy §2.1](spec/project-policy.md#21-admission-and-operational-readiness) |
| Values and schemas | FLOW JSON/1 is bounded. `input`, complete immutable Binding `settings`, and correlated `result` use the three optional conventional Schema/1 files, never shared runtime mailboxes. | [JSON/1](spec/json-values.md), [Schema/1](spec/schema-files.md) |
| Run protocol | Run/1 is full-duplex bounded JSON-RPC over stdio with `flow/run`, `flow/call`, `effect/call`, and request-scoped notification-only `request/cancel`. One live request owns work and uncertainty is never silently replayed. | [Reviewed architecture §5](design-review/60-reviewed-architecture.md#5-flow-run1) |
| Root execution | External frontends submit one active admitted Run Binding, actual input, and a project-local retry key. Hooks always reuse their pinned target/generation and derived-Run key through the same internal admission primitive; callers cannot add trigger data, configuration, or authority. | [Project policy §10](spec/project-policy.md#10-root-run-admission) |
| Services | Service/1 is official but separately conforming. It adds only the lifecycle needed for a pending long-lived JSON service with exact generations, availability, drain, loss, and cancellation. | [Reviewed architecture §6](design-review/60-reviewed-architecture.md#6-flow-service1) |
| Capability contracts | Ordinary Flow calls need no contract. A stable structured service/effect consumer carries the rare self-contained descriptor it expects and references its package-relative path. Compatibility remains exact URI, version, and derived full-descriptor digest; Jig records the digest in normalized state and lock rather than asking authors to copy it into `FLOW.md`. | [Capability Contract/1](spec/capability-contracts.md) |
| Bindings | One immutable Binding configures either an exact FLOW package revision or an export of trusted host capability machinery. Preferred host-capability authoring imports the integration's inert registration token instead of an unexplained bare provider alias. A Binding owns settings, attachments, slots, grants, deadlines, budgets, and admission; each valid Binding is admitted as ready or explicitly unavailable. | [Project policy §2](spec/project-policy.md#2-one-closed-binding-union) |
| Discovery and consent | Generated projects opt into shallow `flows`, `bindings`, and `hooks` fields with one `discover("./root")` primitive; the field supplies the internal member kind and v1 has no glob language. Exact path arrays provide fail-closed membership. Discovery is inert; one aggregate digest-bound compare-and-set admits a complete generation after local consent. V1 defers speculative bulk Binding recipes in favor of generated ordinary declarations. | [Project policy](spec/project-policy.md) |
| Lock bootstrap | A fresh unlocked project may omit `jig.lock`; the first plan proposes it. Locked operations reject absence or drift. | [Project policy §7](spec/project-policy.md#7-consent-and-the-lock) |
| Effects and coeffects | Invocation input/settings/attachments/deadline/budget are the immutable environment. Host-mediated work uses `flow/call` or `effect/call`; coeffect remains theory, not another public API. | [Reviewed architecture §9](design-review/60-reviewed-architecture.md#9-effects-events-hooks-and-agents) |
| Events and Hooks | Events are durable immutable facts in Jig's append-only canonical Journal. Hooks are inert exact Event-source-to-Run admission with interval and derived-Run idempotency, never callbacks or middleware. A Hook may select an existing producer Event or own one registered host Event Source use; custom portable producers remain Services. | [Journal and Hooks/1](spec/journal-and-hooks.md) |
| Agents | Agent Run, Session, and Interactive are separate exact Capability Contracts with owner- and provider-generation-scoped authority, lifecycle, approvals, and observation. The host/operator installs the concrete integration, the Starter/project declares logical Agent Bindings and ceilings, Jig pins/projects/supervises them, and Spindle only consumes an injected slot. A direct FLOW Service export cannot claim partial conformance in v1. | [Agent contracts/1](spec/agents-and-semantic-choice.md) |
| Skills | Each exact `skills/<LocalName>/SKILL.md` subtree is opaque Flow-local source. Agent Run calls select an explicit subset (empty by default), sessions fix a subset at open, and instruction conductors select all immediate package skills. Jig projects only those subtrees read-only for the Agent owner, never copies over provider-native skills, and defines no global precedence, inheritance, or resolver. Selection proves availability, not compliance. | [Agent contracts §3.1](spec/agents-and-semantic-choice.md#31-flow-local-skills) |
| Semantic choice | The deterministic Resolver is kernel machinery. Optional project `semanticChoice: bindingRef("<binding>")` can rank or abstain only within an exact approved allowlist after filtering; runner-local routing uses a separate explicit slot and remains distinct. | [Semantic Choice §5](spec/agents-and-semantic-choice.md#5-semantic-choice), [routing sites §6](spec/agents-and-semantic-choice.md#6-two-intentional-routing-sites) |
| Missing dependencies | Missing, incompatible, unavailable, and ambiguous states exist without an Agent. Missing resolution is terminal for that operation; a separate admitted maintenance Run may stage repair, and only a deliberate new attempt may use the later admitted generation. | [Reviewed architecture §10](design-review/60-reviewed-architecture.md#10-resolution-and-fault-tolerance) |
| Security | Default authority is denied and mediated. Runtime Adapters plan; trusted Sandbox Backends realize inspectable predicates or fail. Wider `trusted-local` authority is explicit and never called confinement. | [Reviewed architecture §11](design-review/60-reviewed-architecture.md#11-security-and-trust), [Runtime Adapters/1](spec/runtime-adapters.md) |
| Lifetime and scheduling | Public wire ownership replaces a distributed Scope/Context/Mount object model, while Jig retains an internal child-first bounded lifetime tree, wait graph, and fenced coordinator state. | [Run ownership §5](design-review/60-reviewed-architecture.md#5-flow-run1), [scheduler §12](design-review/60-reviewed-architecture.md#12-scheduler-and-lifecycle-correctness) |
| User ownership and updates | Visible source is the complete editable truth. Updates perform deterministic `BASE + LOCAL + UPSTREAM` merging before explicitly requested Agent repair; admission and pristine BASE publish and roll back as one recoverable tuple. | [Reviewed architecture §13](design-review/60-reviewed-architecture.md#13-desired-state-direct-editing-and-updates) |
| Inspection | Users can inspect source provenance, pristine BASE, local divergence, staged upstream/merge, visible and active revisions, running pins, and requested-to-realized authority without reading `.jig`. | [Authority inspection §11.4](design-review/60-reviewed-architecture.md#114-host-policy-and-inspection), [source inspection §13](design-review/60-reviewed-architecture.md#13-desired-state-direct-editing-and-updates) |
| Starters | `jig init --bare` or one copied Starter creates fully user-owned source. There is no Starter algebra or ongoing dependency; host Runtime Adapter and Sandbox preferences remain outside Starter output. | [Reviewed architecture §14.3](design-review/60-reviewed-architecture.md#143-starters) |
| Application model | Task, WorkItem, inbox, Kanban, Git/worktree, GUI, and HTTP semantics are Starter/application policy, not Jig kernel ontology. “File-native” means ordinary user-owned source, not a file-shaped application requirement. | [File ownership §13](design-review/60-reviewed-architecture.md#13-desired-state-direct-editing-and-updates), [Starters §14.3](design-review/60-reviewed-architecture.md#143-starters) |
| Runners | Spindle (formerly discussed as Caskada v3) remains an external first-party graph runtime using Run/1 without a privileged in-process path. It carries immutable root input plus one immutable JSON/1 state across edges; ordinary Nodes return the next state and Parallel returns ordered branch results. Only `Outcome` terminates and propagates through nested Flows; a leaf without an edge is an error. Jig has no mapper or result bag. Cordis is a Service-boundary reference only; DSH portability is not a goal. | [Spindle §14.4](design-review/60-reviewed-architecture.md#144-spindle), [Cordis §14.5](design-review/60-reviewed-architecture.md#145-cordis-as-a-reference-integration) |
| Distribution | Git, npm, OCI, local directories, and optional indexes are source adapters. Package identity is provenance plus exact content; no mandatory central registry owns discovery or namespaces. | [Package/1](spec/package-format.md), [Reviewed architecture §3.5](design-review/60-reviewed-architecture.md#35-canonical-package-snapshot) |
| Deferred surface | Public Scope objects, callback handles, streams/subscriptions, per-invocation resource projection into mounted Services, universal graph schemas, runtime profiles, persistent patch overlays, raw provider RPC, and universal sandbox claims remain removed or evidence-gated. | [Reviewed architecture §16](design-review/60-reviewed-architecture.md#16-explicit-removals-and-deferrals) |

When a decision changes, update its normative document first and this index in
the same commit. Do not preserve rejected syntax merely because a historical
review used it.
