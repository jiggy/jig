# Reviewed decision index

This is a traceability aid, not another specification. It lists the durable
architecture decisions and points to their current normative home. Historical
review files remain useful evidence but may contain superseded proposals.

| Area | Reviewed decision | Normative home |
|---|---|---|
| Layer boundary | FLOW owns the portable boundary; Jig owns admission, resolution, authority, lifecycle, and history; runners retain internal control. | [Reviewed architecture §1](design-review/60-reviewed-architecture.md#1-the-architecture-in-one-view) |
| Package | `FLOW.md` is required; its exact-case filename identifies bounded Metadata/1, whose only required fields are `name` and `description`. Ordinary resources and zero or one obvious `flow.<suffix>` implementation need no manifest DSL or mandatory contract. Any future core vocabulary or semantics requires a discriminator which v1 rejects. | [Reviewed architecture §3](design-review/60-reviewed-architecture.md#3-flow-package1), [Package/1 §2](spec/package-format.md#2-flowmd-metadata1) |
| Instruction mode | A Markdown-only package requires an Agent; exact code wins by default; instruction fallback is explicit in both package and Binding and is selected only before launch. A projection-capable Agent provider receives bounded logical resources and returns one complete structured result through Agent Run without another protocol; the projection ABI is release-gated. | [Reviewed architecture §3.3](design-review/60-reviewed-architecture.md#33-instruction-and-exact-implementations), [Agent contracts §3.2](spec/agents-and-semantic-choice.md#32-instruction-conductor-mapping) |
| Runtime selection | FLOW owns no runtime profiles, commands, toolchain versions, or digests. One optional strict selector token narrows trusted host Runtime Adapters; native metadata owns native constraints. Planning pins one implementation recipe or exact unavailability per admission generation; Run/Mount owners derive exact launch after Backend-supervised pinned preparation and never reselect machinery or fallback branches. Ambiguity fails rather than invoking instruction fallback. | [Runtime Adapters/1](spec/runtime-adapters.md), [Project policy §2.2](spec/project-policy.md#22-admission-and-operational-readiness) |
| Values and schemas | FLOW JSON/1 is bounded. `input`, complete immutable Binding `settings`, and correlated `result` use the three optional conventional Schema/1 files, never shared runtime mailboxes. | [JSON/1](spec/json-values.md), [Schema/1](spec/schema-files.md) |
| Run protocol | Run/1 is one root Run per process over bounded full-duplex JSON-RPC stdio. Its only methods are `flow/run`, `flow/call`, `effect/call`, and notification-only `request/cancel`; the root implicitly owns every outbound operation. The closed candidate fixes the six-field invocation, call/result shapes, limits, errors, cancellation, and exit behavior without public Run, parent, provider, authority, or owner-request IDs. Its private TypeScript and Python candidate SDKs expose only the finite component-author projection. The Phase 1 two-peer, package, and instruction-restricted author/evaluator gates are complete. | [Run/1](spec/run-protocol.md), [Run SDK/1](spec/run-sdk.md), [machine schema](spec/machine/run-1.schema.json), [error registry](spec/machine/run-1-errors.json), [Phase 1 disposition](design-review/103-phase-1-flow-foundations.md), [Jig policy §5](design-review/60-reviewed-architecture.md#5-flow-run1) |
| Root execution | External frontends submit one active admitted Run target plus actual input and a project-local retry key. The semantic operation never accepts a raw unreviewed package. Hooks reuse their pinned target/generation and derived-Run key through the same internal admission primitive; callers cannot add trigger data, configuration, or authority. Exact host API/return models remain release-gated. | [Project policy §10](spec/project-policy.md#10-root-run-admission) |
| Services | Service/1 is a first-class, separately conforming target. Its closed wire candidate adds only a pending long-lived JSON service with one fixed dependency set, one fixed export set, attributed Mount/invocation ownership, drain, loss, and cancellation. TypeScript and Python Provider SDKs and a private Jig Host preserve those owners without public Scope objects; the first independent Provider matrix passes, while complete Host/Provider conformance and durable hosting remain open. Shadow-first replacement requires compatible leases; conflicting leases drain and fence before replacement. | [Service/1](spec/service-protocol.md), [Service SDK/1](spec/service-sdk.md), [milestone](design-review/106-service-wire-and-provider-sdk.md), [Reviewed architecture §6](design-review/60-reviewed-architecture.md#6-flow-service1) |
| Capability contracts | Ordinary Flow calls need no contract. A stable structured service/effect consumer carries the rare self-contained descriptor it expects and references its package-relative path. Compatibility remains exact URI, version, and derived full-descriptor digest; Jig records the digest in normalized state and lock rather than asking authors to copy it into `FLOW.md`. | [Capability Contract/1](spec/capability-contracts.md) |
| Bindings and direct targets | One immutable normalized Binding is a tailored configured use of an exact FLOW package revision or trusted host-capability export. A narrowly zero-configuration Run package is instead a tagged direct admitted Flow target; Jig never synthesizes a hidden Binding. Both enter the same admission, authority, idempotency, Hook, revocation, sandbox, and scheduling path and may be admitted ready or exactly unavailable. Package Bindings have no generic `grants`; the host-capability branch remains interface-gated. | [Project policy §2](spec/project-policy.md#2-one-closed-normalized-binding-union), [target disposition](design-review/107-project-authoring-sdk-slice.md) |
| Discovery and consent | Generated projects opt into shallow `flows`, `bindings`, and later `hooks` sources with one `discover("./root")` authoring primitive; the field supplies member kind and v1 has no glob language. Exact path arrays provide fail-closed membership. Discovery is inert: authored values, one descriptor-confined durable capture, and one resolved compare-and-set candidate are separate records. Resolution and apply never reopen visible source. Capture, semantic, and exact reviewed-plan digests answer three different questions. The private package-only aggregate opens one project-root owner, evaluates and retains its complete declaration and Flow artifacts, and feeds the pure linker. A bounded deterministic reducer combines that authentic aggregate with a closed host-planning observation. One exact Python direct-Run candidate now retains and reacquires real package, runtime, Backend, authority, environment, and limit facts end to end, but remains explicitly invocation-local and non-admissible. A strict private package-project projection now proves canonical portable lock evidence and exclusion of host state; upstream provenance, the full public Lock/1 schema, durable lifecycle roots, final resolution, and admission remain open. | [Project policy](spec/project-policy.md), [Project Authoring SDK/1](spec/project-sdk.md), [capture boundary](design-review/108-project-capture-boundary.md), [retained aggregate](design-review/113-retained-project-aggregate.md), [resolution observation](design-review/114-private-resolution-observation.md), [exact Python checkpoint](design-review/115-private-python-exact-run.md), [private lock checkpoint](design-review/116-private-project-local-lock.md), [authoring-value schema](spec/machine/project-authoring-1.schema.json) |
| Lock bootstrap | A fresh unlocked project may omit `jig.lock`; the first plan proposes it. Locked operations reject absence or drift. Ordinary apply durably publishes this inert portable evidence before committing the local admission CAS; a crash between them leaves the lock pending against the complete old generation. Portable authority evidence is requested attachments and capability dependencies, never host policy or enforcement receipts. The implemented package-project projection proves canonical bytes and that exclusion boundary but is intentionally not the final public schema. | [Project policy §7](spec/project-policy.md#7-consent-and-the-lock), [private lock checkpoint](design-review/116-private-project-local-lock.md) |
| Effects and coeffects | Run/1 supplies only input, settings, attachment paths/modes, private scratch, and a finite host deadline. Host-mediated work uses `flow/call` or `effect/call`; coeffect remains theory, not another public API. Provider-specific limits belong to registered settings/grants, not a universal Run budget or wire authority report. | [Run/1 §3](spec/run-protocol.md#3-flowrun), [Reviewed architecture §9](design-review/60-reviewed-architecture.md#9-effects-events-hooks-and-agents) |
| Events and Hooks | Events are durable immutable facts in Jig's append-only canonical Journal. Hooks are inert exact producer/type-to-admitted-Run-target relations with interval and derived-Run idempotency, never callbacks, middleware, or producer lifetimes. Watchers and other producers publish through the Journal outside Hook policy. | [Journal and Hooks/1](spec/journal-and-hooks.md) |
| Agents | Agent Run, Session, and Interactive are separate exact Capability Contract descriptors with owner- and provider-generation-scoped authority, lifecycle, approvals, and observation. The host/operator installs a qualifying integration, the Starter/project declares logical Agent Bindings and ceilings, and Jig pins/projects/supervises them. The provider and resource-projection ABI remains a release gate. | [Agent contracts/1](spec/agents-and-semantic-choice.md) |
| Skills | Each exact `skills/<LocalName>/SKILL.md` subtree is opaque Flow-local source. Agent Run calls select an explicit subset (empty by default), sessions fix a subset at open, and instruction conductors select all immediate package skills. Jig projects only those subtrees read-only for the Agent owner, never copies over provider-native skills, and defines no global precedence, inheritance, or resolver. Selection proves availability, not compliance. | [Agent contracts §3.1](spec/agents-and-semantic-choice.md#31-flow-local-skills) |
| Semantic choice | The deterministic Resolver is kernel machinery. A Flow-call slot is exact or a closed `candidates([...])`; unmapped never means open. Optional project `semanticChoice: bindingRef("<binding>")` can rank or abstain only within the admitted set after filtering. Jig Graph compiles runner-local routing to an ordinary Sley node and named links. The authoring mechanism for a changing reviewed candidate universe remains open. | [Semantic Choice §5](spec/agents-and-semantic-choice.md#5-semantic-choice), [routing sites §6](spec/agents-and-semantic-choice.md#6-two-intentional-routing-sites), [open routing note](design-review/101-default-targets-and-open-routing-candidate.md) |
| Missing dependencies | Missing, incompatible, unavailable, and ambiguous states exist without an Agent. Missing resolution is terminal for that operation; a separate admitted maintenance Run may stage repair, and only a deliberate new attempt may use the later admitted generation. | [Reviewed architecture §10](design-review/60-reviewed-architecture.md#10-resolution-and-fault-tolerance) |
| Security | Default authority is denied and mediated. Inspection preserves `requested -> wouldGrant -> planned -> realized`; Sandbox Backends receipt package containment and trusted host providers separately receipt their enforced projections. Every package begins with read-only prepared bytes and a pinned minimal Runtime Support Closure, private scratch, and protocol stdio—no ambient environment, network, extra file/descriptor, or IPC authority. The only v1 live kernel-file exception is Adapter-selected, separately planned and receipted `root-process-mappings`; it is not package authority or general pseudo-filesystem access. Descendants stay inside one bounded owner envelope and confer no independent authority; v1 has no process grant. Runtime Adapters plan; trusted Sandbox Backends realize inspectable predicates or fail. The private Linux proof enforces per-Run cgroup-v2 CPU/memory/PID limits, admit-before-mutation placement, Bubblewrap isolation, whole-tree kill, post-coordinator cleanup, and zero-leak removal. A process-local, non-admissible Python candidate now pins and passively rechecks the exact Nix runtime and Backend mechanism, executes a Package/1-vendored Run SDK with empty runtime predicates and no entropy device, and disposes its materialization only after a clean fence. Admission still requires a retained complete Adapter artifact, runtime GC leases, crash recovery, and durable recipe decoding. The proof does not publish a Backend API; its Bun evaluator still carries an unresolved private entropy exception, and general Bun remains unavailable because a descendant fails under the root-pinned mappings invariant. | [Reviewed architecture §11](design-review/60-reviewed-architecture.md#11-security-and-trust), [Runtime Adapters/1](spec/runtime-adapters.md), [Phase 2 proof](design-review/105-phase-2-linux-cgroup-proof.md), [exact Python checkpoint](design-review/115-private-python-exact-run.md), [historical blocker](design-review/104-phase-2-security-blocker.md) |
| Lifetime and scheduling | A Run/1 process has one root wire owner, so component calls need no `ownerRequestId`; request IDs remain correlation only. Service/1 uses each pending Host mount/invocation request as the explicit cooperative owner for Provider-originated calls. Jig retains internal durable Run/Mount identities, a child-first bounded lifetime tree, wait graph, operation records, and fenced coordinator state without exposing distributed Scope/Context objects. | [Run/1 §§6–9](spec/run-protocol.md#6-operation-identity), [Service/1 §6](spec/service-protocol.md#6-owner-attributed-calls), [scheduler §12](design-review/60-reviewed-architecture.md#12-scheduler-and-lifecycle-correctness) |
| User ownership and updates | Visible source is the complete editable truth. Updates perform deterministic `BASE + LOCAL + UPSTREAM` merging before explicitly requested Agent repair; admission and pristine BASE publish and roll back as one recoverable tuple. | [Reviewed architecture §13](design-review/60-reviewed-architecture.md#13-desired-state-direct-editing-and-updates) |
| Inspection | Users can inspect source provenance, pristine BASE, local divergence, staged upstream/merge, visible and active revisions, running pins, and requested-to-realized authority without reading `.jig`. | [Authority inspection §11.4](design-review/60-reviewed-architecture.md#114-host-policy-and-inspection), [source inspection §13](design-review/60-reviewed-architecture.md#13-desired-state-direct-editing-and-updates) |
| Starters | `jig init --bare` or one copied Starter creates fully user-owned source. There is no Starter algebra or ongoing dependency; host Runtime Adapter and Sandbox preferences remain outside Starter output. | [Reviewed architecture §14.3](design-review/60-reviewed-architecture.md#143-starters) |
| Application model | Task, WorkItem, inbox, Kanban, Git/worktree, GUI, and HTTP semantics are Starter/application policy, not Jig kernel ontology. “File-native” means ordinary user-owned source, not a file-shaped application requirement. | [File ownership §13](design-review/60-reviewed-architecture.md#13-desired-state-direct-editing-and-updates), [Starters §14.3](design-review/60-reviewed-architecture.md#143-starters) |
| Runners and package names | Sley is an independent live graph runtime using function nodes, links, Flows, shared state, branch input, emit/end, fan-out/combine, retries, recovery, and inspection. Jig Graph owns semantic contracts and compiles them to ordinary Sley objects; ordinary component code composes the FLOW SDK around the graph and launches through Run/1 without a privileged Jig path. Sley is published as `@jigging/sley` for TypeScript and `sley` for Python; intended project packages are `@jigging/jig`, `@flowmd/sdk`, and `flowmd-sdk`/`flowmd_sdk`. Distribution coordinates are not protocol identities. Cordis is a Service-boundary reference only; DSH portability is not a goal. | [Sley §14.4](design-review/60-reviewed-architecture.md#144-sley), [Cordis §14.5](design-review/60-reviewed-architecture.md#145-cordis-as-a-reference-integration) |
| Distribution | Git, npm, OCI, local directories, and optional indexes are source adapters. Package identity is provenance plus exact content; no mandatory central registry owns discovery or namespaces. | [Package/1](spec/package-format.md), [Reviewed architecture §3.5](design-review/60-reviewed-architecture.md#35-canonical-package-snapshot) |
| Deferred surface | Public Scope objects, dynamic Service dependencies/exports, callback handles, streams/subscriptions, universal graph schemas, runtime profiles, persistent patch overlays, raw provider RPC, and universal sandbox claims remain removed or evidence-gated. Host-capability registration, provider projections, host administration APIs, and open candidate-set authoring remain explicit release gates; the direct simple target is no longer open. | [Reviewed architecture §16](design-review/60-reviewed-architecture.md#16-explicit-removals-and-deferrals), [interface gates](design-review/102-public-interface-release-gates.md) |

When a decision changes, update its normative document first and this index in
the same commit. Do not preserve rejected syntax merely because a historical
review used it.
